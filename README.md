## 🌟 プロジェクトの概要：命を繋ぎ、共に成長する「安全のガーディアン」

日本の物流・運輸業界は今、深刻な「物流の2024年問題」の渦中にあります。人手不足、ドライバーの高齢化、そして過酷な連続運行がもたらす「過労運転」による悲惨な重大事故。現場には「運行を止められない」という強いプレッシャーが漂い、ドライバーは「自分が休むと他の仲間に迷惑がかかる」と、無意識のうちに身体の悲鳴や深刻な「隠れ疲労」を隠してハンドルを握ってしまいます。

従来の安全対策は、冷たい If-Else の監視規制にすぎませんでした。「アルコールが出たら自動で罰則」「基準値を超えたら一発アウト」という機械的な減点・監視主義は、現場に息苦しさとシステムの形骸化をもたらすだけでした。

本プロジェクト **「SafeDrive AI Agent」** は、その冷たい規制を**「心身のバイタルに寄り添い、自律的な休息を促す温かいセーフティネット」**へと昇華させるマニフェストです。

スマートウォッチ等のバイタルデータ（睡眠スコア・自律神経ストレス値）と、ドライバー自身がスキャンする運行計画書からAIが自律推測する「目的地までの走行距離・ルート過酷度」を高度に掛け合わせ、本人が「まだ大丈夫」と思っている限界手前のリスクを科学的に検知。状況に合わせて安全判定を自律的にアップグレード / ダウングレードします。

### 🔄 ドライバーの報告がAIを「守護者（ガーディアン）」に成長させる
本システムの核心は、一人のドライバーの帰着時のヒヤリハットや道路工事の報告（日報スキャン）が、AIエージェントの知恵袋へとダイレクトに同期される「現場データ循環（SafeDriveループ）」です。

**ドライバーが日報や危険箇所を報告するだけで、エージェントが自律的に学習して成長し、明日の朝同じルートを走る他のドライバーを全力で助ける「ガーディアン（安全の守護者）」へと自律的に進化していく。**

「誰も奪われない、誰も失わない社会（ゼロ・アクシデント）」を実現するため、現場のドライバー全員でAIの知恵を自己増殖させ、お互いの命を守り合う、温かい次世代型運行管理システムです。

## 🛡️ 徹底的なセキュリティ堅牢化：AIテックリードによる「防弾化」の軌跡

非エンジニアである私が開発を進めるにあたり、プログラムの隙（セキュリティホール）から悪意ある攻撃者が侵入するのを防ぐため、バディである**AIテックリード（Antigravity）および監査AI（Claude等）に「プロ顔負けの最強の盾を取り付けて！」と丸投げして監査を依頼**しました。

すると、AIバディが自律的にコードを全走査し、**計8件に及ぶ徹底的なセキュリティ堅牢化と防弾リファクタリング**を勝手に完了してくれました！azk11自身も驚いたAIによる詳細な監査・実装レポートは以下の通りです。

> ### 📝 【AIテックリード（バディ）によるセキュリティ監査・堅牢化実装レポート】
> 本システムの人命と機微な個人情報を守るため、以下の8つの脆弱性対策および堅牢化リファクタリングを自律設計し、コードへ完璧にコミット・反映しました。
> 
> 1. **【バックエンド】GPT出力の「防弾JSONパース」 (Try-Catchパースリカバリ)**: GPT-5.1が稀に出力する余計なマークダウンフェンス（```json等）や前置きテキストを正規表現で自動検知して除去。さらに予期しない改行や閉じ忘れに対しても頑強にパースします。
> 2. **【バックエンド】JSONパース例外処理の徹底ハンドリング**: JSONパースエラー時のプロセス破綻（クラッシュ）を完全に防ぐ、内側 try-catch によるフォールバック判定へのリカバリ処理を2箇所に実装。
> 3. **【バックエンド】スタックトレース等の例外情報漏洩の防止**: エラーハンドリングにおいて、エラーのスタックトレースや内部APIパスなどをクライアント側へ一切返却しない「防漏洩エラー設計」を実装。
> 4. **【管理画面】動的生成箇所におけるXSS（クロスサイトスクリプティング）の排除**: `admin.js` 内でドライバーの入力やAIメッセージをHTMLへ動的レンダリングする際、`img src` やテキスト挿入によるスクリプト注入を完全に無効化。
> 5. **【ドライバー画面】innerHTMLの完全廃止とエスケープ徹底**: `app.js` 内のDOM操作において `innerHTML` や無防備な動的文字列結合を排除し、XSS攻撃を完全に無効化するサニタイズ処理を実装。
> 6. **【フロントエンド】storageイベントリスナーの重複リーク防止**: ブラウザの `localStorage` 監視イベントが多重に登録されてブラウザのメモリが食いつぶされるリークを try-catch および重複排除ロジックで修正。
> 7. **【シミュレーター】アルコール検知の「無条件レッドガード」**: AIおよびシミュレーター判定ロジックの最下部に「アルコールが0.00mg/L超ならあらゆるコンテキストをオーバーライドして運行停止にする」という防弾ガードを実装。
> 8. **【フロントエンド】GPS位置情報の環境依存プライバシーマスク**: デモやデバッグ時の生座標を適切にマスクしつつ、GPSが取得できない場合のフォールバックを安全に実装。

## 📊 安全運行判定マトリクス（ヒートマップ）

従来のアルコール一辺倒の判定基準を超え、本人の睡眠状態と自覚疲労、スマートウォッチで測定したバイタル（HRVストレス比）を高度に掛け合わせた、本システム独自の総合安全判定ロジック（ヒートマップ）です。

| 睡眠スコア (縦) \ 疲労度・ストレス (横) | 良好 (万全 & 低) | 注意 (やや疲れ & 中) | 警告 (重い & 高) |
| :--- | :--- | :--- | :--- |
| **70点以上 (十分な回復)** | 🟢 **グリーン (良好)**<br>通常運行可能 | 🟡 **イエロー (要警戒)**<br>適宜水分補給・休憩指示 | 🔴 **レッド (運行停止)**<br>※二重リスク・交代要請 |
| **51点〜69点 (睡眠不足)** | 🟡 **イエロー (要警戒)**<br>こまめな休憩指示 | 🟡 **イエロー (要警戒)**<br>1時間ごとのSA休憩指示 | 🔴 **レッド (運行停止)**<br>※二重リスク・対面確認 |
| **50点以下 (極度不足)** | 🔴 **レッド (運行停止)**<br>睡眠極度不足のため停止 | 🔴 **レッド (運行停止)**<br>重大リスクのため停止 | 🔴 **レッド (運行停止)**<br>絶対運行不可・交代要請 |

### 判定しきい値ルール（実務遵守のゼロトレランス）

本システムは、日本の運行管理実務で絶対に譲れない**「アルコール 0.00 mg/L 絶対主義（無検出厳守）」**をシステムレベルで徹底しています。0.01 mg/L でも検知された場合は、AIやシミュレーターの如何なる良好判定もオーバーライドし、即時に運行を物理的・運用的にロックします。

1. 🔴 **レッド (運行停止 / Danger)**
   * **アルコール測定値**: `0.00 mg/L` 超（0.01 mg/L 以上が検出された場合は無条件で即運行停止。※法律上の酒気帯び運転基準 `0.15 mg/L` を待たず、点呼実務規程を徹底遵守します）
   * **睡眠極度不足**: 昨夜の睡眠スコアが `50点` 以下
   * **二重リスク検知**: 昨夜の睡眠スコアが `70点` 未満、かつ（体感自覚疲労が「重い」またはHRVストレスが「警告/高」）
   * **長距離・過酷運行と判定され、かつ中度の健康リスク**（睡眠スコア70未満や疲労・ストレスあり）が重複した過酷コンテキスト時
2. 🟡 **イエロー (要警戒 / Warning)**
   * 昨夜の睡眠スコアが `70点` 未満、または自覚疲労が「やや疲れ」「重い」、またはHRVストレスが「注意」「警告」
   * **環境熱中症リスク**: 現在地周辺的暑さ指数（WBGT）が `28.0℃` 以上
3. 🟢 **グリーン (良好 / Success)**
   * 上記のどれにも該当しない、心身ともに万全な状態

## 🚀 【完全初心者向け】Azure各種サービスの立ち上げとキー設定ガイド

Azureポータルでリソースを作成し、本番環境と接続するための5つのステップです。

### STEP 1: Azure Cosmos DB (データベース) の作成
1. Azureポータルの検索バーで「**Azure Cosmos DB**」を検索し、選択します。
2. 「**＋作成**」を押し、「**Azure Cosmos DB for NoSQL**」を選択します。
3. 必要項目を入力します：
   - **ワークロードの種類**: 「Learning」または「開発テスト (Dev/Test)」を選択します（デモ・開発用に最適でコストを抑えられます）。
   - **リソースグループ**: 「新規作成」で `safedrive-rg` を作ると管理が楽です。
   - **アカウント名**: 英小文字と数字で一意の名前（例: `safedrivedb-1234` のように、末尾の「xxx」部分は**お好きな数字でも問題ありません**。世界で1つだけの名前である必要があります）を決めます。
   - **場所**: `Japan East (東日本)` を推奨。
   - **容量モード**: 「サーバーレス」を選択（ハッカソン期間中はコストがほぼゼロになります！）。
4. 「確認および作成」➔「作成」を押します（数分待ちます）。
5. 作成完了後、リソースへ移動し、左メニューの「**キー (Keys)**」から以下をコピーし、`api/local.settings.json` に貼り付けます。
   - `URI` ➔ `COSMOS_DB_ENDPOINT` へ
   - `プライマリキー (Primary Key)` ➔ `COSMOS_DB_KEY` へ

> [!TIP]
> **💡 データベースやコンテナーの構築は「完全自動」です！**
> 本プロジェクトの API（`CheckIn` & `GetLogs`）には、Cosmos DB接続時にデータベース `SafeDriveDB` とコンテナー `CheckIns` が存在しない場合、パーティションキー `/driverId` で**自動的にバックグラウンド構築する自律初期化ロジック**が組み込まれています。そのため、Azure Portal 上で手動でデータベース設計やコンテナー作成を行う手間は一切不要です！

### STEP 2: Azure AI Document Intelligence (OCR) の作成
1. ポータルで「**Document Intelligence**」を検索・選択します。
2. 「**＋作成**」を押します。
   - **価格レベル**: `F0 (無料)` があれば選択。無ければ `S0` を選択。
3. 作成完了後、リソースへ移動し、左メニューの「**キーとエンドポイント**」から以下をコピー・貼り付けます。
   - `キー 1` ➔ `DOCUMENT_INTELLIGENCE_KEY` へ
   - `エンドポイント` ➔ `DOCUMENT_INTELLIGENCE_ENDPOINT` へ

### STEP 3: Azure OpenAI Service (GPT-5.1) の作成とモデルデプロイ
1. ポータルで「**Azure OpenAI**」を検索・選択して作成します。
2. 作成完了後、リソースの「**キーとエンドポイント**」から以下をコピー・貼り付けます。
   - `キー 1` ➔ `AZURE_OPENAI_KEY` へ
   - `エンドポイント` ➔ `AZURE_OPENAI_ENDPOINT` へ
3. Azure OpenAIポータル内の「**モデルのデプロイ (Azure AI Studio)**」に移動し、**「＋モデルのデプロイ」➔「基本モデルのデプロイ」**を押します。
   - モデルに **`gpt-5.1`** を選択。
   - デプロイ名（Deployment Name）を **`gpt-5.1`** にしてデプロイします。

### STEP 4: Azure Static Web Apps (SWA) の作成とGitHub自動デプロイ
1. ポータルで「**静的 Web アプリ (Static Web Apps)**」を検索・選択し、作成します。
2. 「**GitHubでサインイン**」を選択し、今回作成したリポジトリ（`safedrive-ai-agent`）と `main` ブランチを選択します。
3. **ビルドの詳細**セクション：
   - プリセット: `Custom` を選択
   - アプリの場所: `/src`
   - APIの場所: `/api`
   - 出力先: 空欄のまま
4. 「確認および作成」➔「作成」を押すと、**GitHub Actionsが自動的に生成・実行され、数分で全世界へアプリが自動公開されます！**
5. アプリの概要タブにある「URL」をクリックすると、あなたの本番フロントエンド画面が開きます！

> [!IMPORTANT]
> **💡 別端末リアルタイム同期（本番接続）の開通Tips**
> デプロイ完了後、本番の Static Web Apps (SWA) で別端末のリアルタイム遠隔同期を完全に機能させるには、SWAの Azure Portal 画面の左メニュー **「設定」➔「環境変数」**（または「構成」）にて、以下の4つのアプリケーション設定を必ず登録（保存）してください。これらを登録しないと、セキュリティ保護のための「模擬シミュレーターモード」が作動し、DB接続がスキップされます。
> - `COSMOS_DB_ENDPOINT` ➔ Cosmos DBの `URI`
> - `COSMOS_DB_KEY` ➔ Cosmos DBの `プライマリキー`
> - `COSMOS_DB_DATABASE_NAME` ➔ `SafeDriveDB`
> - `COSMOS_DB_CONTAINER_NAME` ➔ `CheckIns`

### 1. 【なりすまし/不正回避の根絶】ゼロトラスト顔・声紋ハイブリッド認証
* **課題**: アルコール検知や極度疲労が出たドライバーによる、同僚や家族への「身代わり打刻」の防止。
* **セーフティネット構想**: 撮影時に「右を向く」「まばたきを2回する」といったランダムな指示を与える**「動的生体検知（Liveness Detection）」**を実装。また、「本日も安全運転を誓います」という音声宣誓から声紋認証と同時に、脳梗塞や酩酊による滑舌の乱れを自動分析します。

### 2. 【再測定すり抜けの防止】Cosmos DBによるサーバーサイドロックアウト管理
* **課題**: アルコールが検出された際、0.00mg/Lが出るまで何度も口をすすいで吹き直し、合格画像だけを提出する「すり抜け行為」の防止。
* **セーフティネット構想**: 1回でもアルコールが検知された場合、ブラウザの `localStorage`（フロント側）での容易な改ざんやバイパスを防ぐため、**Cosmos DBで測定セッションのステートをセキュアに一元管理**。アルコールが揮発するまでの医学的インターバルである「15分間」はサーバー側で再測定を強制ロックアウトします。また、未提出であっても測定を試みた「検知履歴」はバックグラウンドで管理システムに即時共有され、管理画面上に「過去30分以内に検知失敗履歴あり（要対面点呼）」と警告表示される仕様にします。

### 3. 【警告無視の公道進入を防ぐ】車両イモビライザーAPI物理ロック
* **課題**: システムが「レッド（運行停止）」や「要警戒」を出しても、現場のドライバーが無視してキーを回し、公道へ進入してしまう問題。
* **セーフティネット構想**: スマート車載器や車両のCANバス/MaaS APIと連動。乗務前打刻が「グリーン（良好）」または管理者により遠隔承認された場合のみ、エンジン始動が許可される**「スマートイモビライザー連携」**を確立し、リスク車両の公道進出を物理的に防ぎます。

### 4. 【走行中の脳卒中・突然死の救済】ウェアラブル脈拍リアルタイム監視
* **課題**: 出発前は万全でも、走行中（例: 高速道路走行中）の突然の心機能停止、脳梗塞、急激な居眠りなどの検知。
* **セーフティネット構想**: 運転中にスマートウォッチからバックグラウンドで心拍数を常時取得。心拍停止や異常値を検知した瞬間に、自動でハザードを点滅させ、本社運行管理および救急機関へGPS連動でサイレントSOSを発報。さらに先進安全運転支援（ADAS）と連動し、車両を自動で路肩に安全停車させる自律路肩退避とリンクします。

### 5. 【家族とつながる優しさのネット】心理的セーフティネット
* **課題**: 運行管理者からの「運行停止」命令だけでは、プレッシャーからドライバーが体調不良を隠してしまう問題。
* **セーフティネット構想**: 深刻なバイタル異常を検知した際、本人の家族のアカウントへも「お父さんは今日、少しお疲れのようです。帰宅後はゆっくり休めるよう声をかけてあげてください」といった温かい自動メッセージ（RAG）を送信。ドライバーが周囲の理解のもとで、無理をせず「自律的に休む選択」ができる優しい社会インフラを築きます。
